### 4-1b 서식 완성 (같은 날 추가)
rhwp API가 이미 갖고 있는 서식을 도구줄에 연결했다(WASM 추가 0B). 도구줄은 같은 `.btn`·`.select`만 쓴다.
- 글자: **글꼴**(문서가 쓰는 글꼴 + 흔한 글꼴 목록, 브라우저는 설치 글꼴을 알려주지 않는다), 크기, 굵게·기울임·밑줄·**취소선**, 글자색·**형광펜(음영색)**, **자간·장평**(−/+).
- 문단: 정렬, **줄 간격**(100~300%), **왼쪽 여백 늘리기·줄이기**(한 단계 약 10pt), **문단 부호 보기**(보기 옵션이라 문서·변경 표시에 영향 없음).
- 구현 중 찾은 rhwp 특성(어댑터에서 처리, 포크 패치 없음): (1) 글꼴 번호는 언어 7칸마다 따로라 칸마다 `findOrCreateFontIdForLang`으로 구해 넣어야 한다(같은 번호를 7칸에 넣으면 영어 글자가 다른 글꼴이 됨). (2) 취소선·밑줄은 `true`만 주면 "선 모양 없음"인 글자에서 **저장 때 선이 사라진다** → 선 모양(실선)을 함께 지정한다. 코퍼스 서식 점검이 둘 다 잡았다.
- 시험: E2E 2개 추가(서식 일괄 적용 후 저장본의 글꼴·취소선·형광펜·자간·장평·줄 간격·여백 확인, 문단 부호), 퍼저에 서식 연산 추가, 코퍼스 왕복에 서식 보존 점검 추가: **1,171개 중 1,170개에서 서식이 저장본에 남음**(예외 `누름틀-2024.hwp`, 누름틀 필드 문서).

### 입력 지연 (설계 예산: 글자 입력 → 화면 반영 p95 ≤ 50ms)
키를 누른 순간부터 쪽 그림(`<img>`)이 새로 불러와지는 순간까지를 쟀다(`tests/e2e-edit.mjs`).

| 문서 | p50 | p95 | 비고 |
|---|---|---|---|
| 작은 문서(3쪽, `hwp_table_test.hwp`) | 약 55~60ms | 약 70~89ms | Worker 쪽(입력+쪽 그림 만들기)은 약 10~20ms, 나머지는 브라우저가 SVG 쪽 그림을 해석·그리는 시간(약 35~50ms) |
| 35쪽 문서(`2022년 국립국어원 업무계획.hwp`) | 약 70~90ms | 약 220~300ms | 글자 하나마다 rhwp가 문서 전체를 다시 쪽 나눈다(`insertText` 약 30ms, 작은 문서는 1.5ms) |

- **(측정 편차)** 같은 시험을 CPU가 한가할 때 다시 돌리니 작은 문서 p50 46ms·p95 61ms, 35쪽 문서 p50 52ms·p95 105ms로 위 수치보다 좋았다. 이 환경의 측정은 부하에 따라 2배 이상 흔들린다.
- **예산 50ms를 이 시험 환경에서는 안정적으로 충족하지 못했다.** 환경은 소프트웨어 렌더링·공유 CPU(4코어) 샌드박스라 일반 PC보다 몇 배 느릴 수 있다. 그래서 시험의 한도는 느슨하게(작은 문서 120ms, 큰 문서 400ms) 두고 실제 수치를 출력한다(`EDIT_LAT_P95`, `EDIT_LAT_P95_LARGE`로 조정). **오너 기기에서 같은 시험을 돌려 확인이 필요하다**(오너 결정/확인 요청 #28).
- 이미 적용한 개선: 글자를 치는 쪽만 즉시 다시 그리고, 나머지 보이는 쪽은 입력이 350ms 멈춘 뒤에 그린다(처음에는 글자마다 보이는 쪽 3장을 다시 그려 입력이 그 뒤에 줄을 섰다).
- 남은 큰 비용은 (1) 큰 문서의 전체 재조판(엔진 내부, 포크 패치 없이는 어려움), (2) SVG 쪽 그림 해석. 필요하면 Canvas 렌더 전환이나 글자 입력 줄만 먼저 덧그리는 방식을 다음 단계에서 검토한다.

## 4. 구현 중 찾아 고친 것 (퍼저·E2E가 잡았다)
1. **Enter가 개체가 든 문단에서 엉뚱한 곳을 나눔**: rhwp `splitParagraph`만 오프셋을 "논리 오프셋"(글자 + 글자처럼 놓인 표·그림 1칸)으로 받고 입력·삭제·커서·서식은 글자 오프셋으로 받는다. 문단 앞에 표가 있으면 개체 수만큼 앞에서 잘렸다. → 나눈 뒤 앞 문단 글자 수를 확인하고 다르면 되돌려 한 칸씩 늘려 다시 한다(`opSplit`).
2. **Backspace로 문단 합치기가 안 되는 경우(표가 든 앞 문단)에도 변경·되돌리기 항목이 생김**: 합쳐지지 않으면 변경이 없는 것으로 처리하고 되돌리기 항목을 버린다. 합친 뒤 캐럿은 앞 문단의 글자 수로 정한다.
3. **HWP 3.0 판별**: `getDocumentInfo().hwp3Variant`는 3.0 문서에서도 false였다. 버전 문자열("3.")로 판별한다.
4. **캐럿 좌표를 못 구하는 위치**(그림만 있는 문단 등): 예외가 아니라 `null`로 두어 편집은 적용하고 캐럿만 그리지 않는다.
5. **되돌리기 뒤 캐럿 위치**: 편집 직전·직후의 캐럿을 되돌리기 항목에 같이 저장해 그 자리로 돌아간다.
6. **빠르게 칠 때 글자 순서가 뒤집힘**("Hello"→"olleH"): 모든 사용자 동작을 하나의 대기열로 직렬화하고 실행 시점의 위치를 읽도록 바꿨다.
7. **쪽 번호 칸에서 Enter를 치면 문서에 줄이 들어감 / 편집 시작 직후 쪽 이동이 되돌려짐**: 다른 입력 칸에서 포커스를 빼앗지 않게, 시작 때 놓는 캐럿은 화면을 움직이지 않게 고쳤다.
8. **좁은 화면에서 저장 단추가 가려짐**: 도구줄을 접히게 했다.

## 5. 알려진 한계 (4-1)
- 머리글·바닥글·각주·글상자·도형 안의 글은 아직 편집하지 못한다(눌러도 "아직 편집할 수 없습니다" 안내, 문서는 안 바뀜).
- 붙여넣기는 글만(서식·그림 없음). 그림·표 삽입·삭제, 표 구조 편집(행·열·합치기), 찾아 바꾸기는 4-1 범위 밖.
- 글꼴 목록은 이 문서가 쓰는 글꼴 + 흔한 글꼴이다. 기기에 없는 글꼴을 고르면 문서에는 그 이름이 저장되지만 화면에는 대체 글꼴로 보인다.
- 되돌리기는 60단계(스냅샷 방식, 큰 문서는 메모리를 쓴다). 입력은 1.5초 단위로 묶는다.
- 편집한 뒤 검색 결과 강조는 갱신되지 않는다(다시 검색).
- 모바일 터치 선택 핸들·가상 키보드 최적화는 모바일 단계(6단계) 몫이다. 도구줄 레이아웃만 좁은 화면에서 접힌다.
- 저장 점검은 문단 수·길이·앞 40자와 쪽 수를 본다. 그림·서식·개체가 사라진 것은 못 잡는다(rhwp의 손실 보고서는 믿을 수 없어 쓰지 않는다).
- 큰 문서(35쪽 이상)에서 입력 지연이 예산을 넘을 수 있다(위 3절). 열기만 8초 넘게 걸린 문서는 "편집"을 누를 때 "편집이 매우 느릴 수 있습니다" 확인창을 띄운다(병리 사례 `issue2063_huge_cellbreak_table.hwp`는 열기 195초, 글자 하나에 분 단위라 사실상 편집 불가).

## 7. 4-1c~f: rhwp 편집 API 나머지 연결 (오너 요청 "API에 있는 기능 끝까지")
rhwp WASM의 편집 API(약 475개) 중 문서를 바꾸고 화면에 쓸 수 있는 것을 도구줄(탭: 서식·입력·표·개체·쪽·찾기·보기)에 연결했다. 추가 WASM 없음. 구조: 범용 `api`·`q` 작업(허용 목록 안의 API 이름만 호출, 실패하면 직전 스냅샷으로 복원) + 기능별 모듈(`ed-table.js`·`ed-objects.js`·`ed-page.js`·`ed-misc.js`) + 값 입력 대화상자(`ed-ui.js`).

- 예산: 편집 코드 **30,154B**/40,000B(editor 22,602 + hwpedit 7,552), 첫 화면 합계 3,151,017B/3,340,000B.
- 시험: 편집 E2E **28개**, 퍼저 모드 4가지(표·개체·쪽·기타를 섞어 무작위 편집 → 엔진이 거부한 편집 뒤 문서가 그대로인지, 저장 점검, 되돌리기 전부 → 원본 구조), 왕복 코퍼스 서식 보존.
- 구현 중 찾아 고친 것: (1) 표 단추가 한 박자 늦은 상태를 읽던 경합(실행 시점에 Worker에서 새로 읽도록), (2) 모달 대화상자 뒤 입력창이 글자를 못 받는 상태(포커스를 뺐다 다시 줌), (3) 대화상자 안 숫자 칸의 브라우저 검증이 제출을 막던 문제, (4) 엔진이 거부·실패한 편집이 문서를 반쯤 바꿔 두던 것(직전 스냅샷으로 복원), (5) 표만 있는 문단의 맨 앞 Enter, (6) 되돌리기 뒤 캐럿이 문단 길이를 넘던 것(범위 안으로 끌어옴), (7) 포인터 이벤트에는 클릭 횟수가 없어 두 번 클릭을 직접 셈, (8) 복사 때 엔진 클립보드를 채워 서식째 붙이기가 선택 갱신 경합에 흔들리던 것.
- **쓰지 않은 API**: `setControlZOrderAt` 등 `…ControlAt`·`…Api` 계열의 일부는 wasm이 죽는다(`memory access out of bounds` 확인) — 같은 기능을 `changeShapeZOrder`·`set*Properties`로 대신했다.

### 4-1g 추가
- **번호 모양 사전 설정**: 서식 탭 목록에서 `가. 나.` `① ②` `I. II.` `A. B.` `ㄱ. ㄴ.` `일. 이.` 선택(엔진 `createNumbering`, 한 번 만든 모양은 재사용).
- **개요…**(보기 탭): 번호 매겨진 제목 목록(`getOutlineNavigation`)에서 골라 그 문단으로 이동.
- **스타일 갱신**: 스타일… → "현재 모양으로 스타일 갱신"(캐럿 자리의 글자·문단 모양을 스타일 정의에 반영, `updateStyleShapes`).
- 시험: E2E 31개 통과(번호·스타일 갱신, 개요 이동 2개 추가).

### 4-1h 머리글·바닥글·각주 제자리 편집
- **두 번 누르기**: 머리글·바닥글(있을 때)·각주 영역을 두 번 누르면 본문처럼 그 안에서 바로 입력·줄바꿈·지우기·선택·단어/줄 이동·글자/문단 서식·되돌리기를 한다. 도구줄에 "머리글 편집 중 — Esc를 누르면 본문으로 돌아갑니다"가 뜨고 **Esc**로 들어가기 전 본문 위치로 돌아온다.
- 위치 모델 확장: `pos.hf = {k:'h'|'f'|'n', a, pg, bp, c}`(머리글·바닥글은 적용 쪽, 각주는 달린 본문 문단·개체 번호). 같은 작업(입력·삭제·줄 나누기·합치기·범위 지우기·선택 영역·서식)이 `pos.hf`가 있으면 `…InHeaderFooter`·`…InFootnote` API로 간다. 머리글·바닥글은 모든 쪽에 보이므로 쪽 전체를 다시 그린다.
- 끌어서 선택: 머리글·바닥글 안에서 끌면 영역 밖(둘째 줄 등)으로 나가도 그 안의 가장 가까운 자리로 잡고, 각주는 다른 각주 위로 끌어도 선택을 유지한다.
- 엔진 보정: `getFootnoteInfo`가 글 안의 제어 문자(탭·줄바꿈)를 JSON 이스케이프하지 않아 읽기에 실패한다 → 실패하면 제어 문자를 이스케이프해 다시 읽는다.
- 시험: E2E(머리글에 입력·줄바꿈·지우기, 각주 앞에 입력, Esc, 저장본 확인), 퍼저 `--hf`(안쪽 입력·줄바꿈·지우기·서식·이동을 섞고 본문 불변·거부된 편집 뒤 불변·캐럿 범위를 검사). 편집 코드 32,702B/40,000B.

### 4-1i~k 개체 묶기·회전·글 넣기
- **묶기**: 개체를 고른 뒤 Shift+누르기로 더 고르면(점선 틀) 개체 탭 "묶기"로 하나의 묶음(`groupShapes`)이 된다. "묶음 풀기"로 되돌린다. 여러 개를 고른 채 Delete는 모두 지운다.
- **회전 손잡이**: 도형·그림의 선택 틀 위에 둥근 손잡이를 끌면 가운데를 기준으로 돌아간다(위가 0도, 시계 방향, Shift는 15도 단위, `rotationAngle`). 이미 돌아간 개체는 틀도 같이 돌아가 있다.
- **글 넣기·글 떼기**(개체 탭): 도형에 글상자를 붙여(`setTextBoxAt`) 안에 글을 쓴다. 빈 글상자는 엔진이 캐럿 좌표를 주지 않아 틀 왼쪽 위 안쪽에 캐럿을 두고, 첫 글자를 넣으면 엔진이 좌표를 준다. 글 떼기는 안의 글이 없어진다는 확인을 거친다.
- 시험: E2E 3개(묶기·풀기 저장 확인, 회전 90도 저장 확인, 글 넣기 저장 확인), 퍼저 개체 모드에 묶기·글상자 붙이기·떼기 추가.

### 4-1l 눈금자·목차·선 끝점·칸 안 개체·중첩 표
- **눈금자**(보기 탭): 캐럿이 있는 쪽의 가로 눈금(cm)과 쪽 여백을 보여 주고, 문단의 왼쪽 여백·첫 줄 시작·오른쪽 여백 표지를 끌어 바꾼다(선택한 문단 전체에 적용). 표 칸·머리글·각주 안에서는 표지를 숨긴다.
- **목차 넣기**(입력 탭): 번호가 매겨진 제목(개요)으로 "제목 ······ 쪽" 목차를 캐럿 자리에 글로 넣는다(단계·점 줄 선택). 글이라 문서가 바뀌면 다시 넣어야 한다.
- **선 끝점**: 선을 고르면 시작·끝 점 손잡이를 끌어 옮긴다(`moveLineEndpoint`).
- **여러 개체 함께 옮기기**: Shift+누르기로 고른 여러 개체를 하나 끌면 모두 같은 만큼 옮겨진다.
- **표 칸 안 개체**: 칸 안 그림·도형도 눌러 고르고 크기·속성·회전·지우기(그림만)를 한다(엔진의 `…CellPictureProperties/CellShapePropertiesByPath`). 칸 안 개체에는 순서·복사·묶기·글 넣기를 막는다.
- **중첩(안쪽) 표**: 안쪽 표 칸에서 "너비 같게·높이 같게"와 "표 지우기"가 된다(`resizeTableCellsByPath`, `deleteCellTableControlByPath`). 줄·칸 넣기·지우기·합치기·나누기는 엔진에 경로 버전이 없어 막는다.
- 시험: E2E 6개(눈금자 끌기, 목차, 선 끝점, 여러 개 함께 옮기기, 칸 안 그림, 중첩 표) 추가, 편집 E2E 42개 통과.

### 4-1m 터치 선택 손잡이
- 손가락·펜으로 쓸 때, 선택 영역 양 끝(첫 줄 왼쪽 아래·마지막 줄 오른쪽 아래)에 안드로이드처럼 물방울 손잡이가 나타난다. 끌면 그 끝이 따라 움직여 영역이 넓어지거나 줄고, 반대쪽 끝을 넘기면 서로 뒤바뀐다. 손잡이를 화면 위·아래 가장자리로 끌고 가면 문서가 스크롤된다. 마우스를 쓰면 보이지 않는다(마지막 입력 장치로 판단).
- 영역을 만드는 길: **길게 누르기**(0.48초, 움직이면 취소)로 단어 선택, 두 번 누르기(단어)·세 번 누르기(문단)는 그대로. 손가락으로 끌면 화면만 스크롤되고 선택은 생기지 않는다(예전에는 스크롤 시작 전 몇 픽셀이 작은 선택으로 남을 수 있었다). 터치 길게 누르기의 시스템 메뉴는 막는다.
- 손잡이는 쪽 위에 따로 얹는 요소라 선택을 다시 그려도 끌기가 끊기지 않고, 크기는 확대 비율과 상관없이 일정하다(44px 누름 영역).
- **고친 것**: 한 표 칸 안의 글 선택이 칸 전체(칸 블록)로 표시되고 서식·삭제가 칸 전체에 적용되던 문제 — 서로 다른 칸에 걸칠 때만 칸 블록으로 다룬다.
- 시험: E2E 1개 추가(스크롤만 되는지, 길게 누르기, 양 끝 끌기·안쪽으로 줄이기·끝을 넘기기, 표 칸 안 단어, 해제 시 손잡이 사라짐), 편집 E2E 43개 통과. 편집 코드 37,456B/40,000B. 실제 안드로이드 기기 확인은 아직 못 했다(Chromium 터치 에뮬레이션 기준).

### 4-1n 편집 단추 강조·도구줄 아이콘
- 상단바의 **편집** 단추를 첫 번째(로고 바로 뒤)로 옮기고 강조색(기본 단추)으로 바꿨다. 편집할 수 있는 문서에서는 "파일 열기"가 보통 단추로 물러난다(편집이 안 되는 문서에서는 그대로). 편집 중에는 옅은 강조(눌림) 모양.
- 편집 도구줄의 탭(서식·입력·표·개체·쪽·찾기·보기)과 저장 옵션·저장 단추에 선 그림 아이콘을 붙였다(기존 되돌리기·정렬 아이콘과 같은 16px 선 스타일, 글자색을 따라가 다크 테마도 맞다). 탭 안의 세부 단추는 글자만이다.
- 시험: 불안정하던 E2E(이동 시험의 캐럿 상자 읽기)를 안정화.

### 아직 없는 것(API는 있으나 연결하지 않았거나 불완전)
- 각주 안에서는 글자 서식을 바꿀 수 없다(엔진에 API가 없다, 문단 서식만 가능). 머리글·바닥글·각주 안에서는 표·개체·찾기 등 본문 좌표 기능을 막는다(Esc로 본문에 돌아온다). 머리글 대화상자(쪽 탭)도 그대로 쓸 수 있다.
- **엔진에 API가 없어 만들 수 없는 것**: 캡션(`attachCaptionAt`은 캡션 자리만 만들고 글을 그리지도 고치지도 못한다), 바탕쪽(API 없음), 다각형·곡선 점 편집(`setShapeProperties`의 `polygonPoints`는 받아도 반영되지 않고 점을 읽는 API도 없다), 연결선 연결 대상(`connectorType`만 있고 대상 지정 API가 없다), 중첩 표의 줄·칸 편집, 칸 안 도형 지우기, 구역 2 이상 도형의 글 넣기(`setTextBoxAt`이 구역을 받지 않는다).
- 스타일의 세부 모양 편집(캐럿 자리 모양으로 갱신은 됨), 번호 모양 완전 사용자 정의(가. ① I. A. ㄱ. 일. 사전 설정은 됨), 눈금자의 탭 정지·쪽 여백 끌기(여백은 쪽 탭 대화상자), 갱신되는 목차(필드).
- HML 저장. 다른 프로그램으로 복사할 때 서식(HTML)은 내보내지 않는다(글만).
- 새 기능은 데스크톱 브라우저 기준이다. 터치는 선택 손잡이(4-1m)까지만 있고, 그 밖의 모바일 편집 화면(도구줄 배치·가상 키보드 대응)은 6단계.
