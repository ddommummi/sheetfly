# 자체 조판 엔진 설계 (3단계, 2026-10-19)

> 오너 결정(2026-10-19): "직접 조판엔진 제작". D-030의 A(BetterOffice)와 B(office_oxide 읽기 보기) 사이에서, **office_oxide를 수정하지 않고 그 IR 위에 우리 조판 층을 얹는** 방식으로 간다. 이 문서는 범위·구조·검증 기준이다. 구현 진행에 따라 갱신한다.

## 구조
```
DOCX 바이트 ──office_oxide(wasm, 2.3MB·brotli 0.77MB 수준)──▶ IR(JSON) ──조판(JS, Worker)──▶ 쪽별 표시 목록 ──SVG──▶ 기존 뷰어
```
- **IR 공급**: `third_party/office_oxide`(서브모듈, `5d183f4` v0.1.15 고정, 수정 없음). `scripts/build-docx-wasm.sh`가 rhwp와 같은 Rust 1.93.1로 빌드(실측 2분 34초, wasm-opt 포함), `wasm-bindgen` 0.2.129 CLI는 `scripts/ensure-wasm-bindgen.sh`가 준비.
- **조판**: `apps/web/src/docx/` (바닐라 JS, 프레임워크 없음). 줄바꿈·쪽 나눔·표·목록·머리글/바닥글. 입력은 IR뿐이고 출력은 쪽별 "표시 목록".
- **글자 폭 측정**: Worker의 `OffscreenCanvas.measureText`. **그리는 쪽(브라우저 SVG 텍스트)과 같은 글꼴 엔진을 쓰므로 측정과 그림이 일치**하고, 한글 글꼴을 번들에 싣지 않는다(사용자 기기 글꼴 사용). 대가: 기기에 글꼴이 없으면 대체 글꼴로 폭이 달라진다(D-032 한계).
- **그리기**: 표시 목록 → SVG 문자열 → 기존 `<img>` blob 파이프라인(스크립트·외부 로드 불가). 가상화·확대·검색은 기존 코드를 재사용한다. Worker 메시지 계약(`init`/`open`/`render`/`search`/`close`/`warmup`)을 그대로 구현한다.

## IR이 주는 것 / 안 주는 것 (office_oxide 0.1.15, 실측)
| 있음 | 없음/한계 |
|---|---|
| 글자별 서식(크기 half-pt, 굵게/기울임/밑줄/취소선, 색, 형광펜, 위/아래 첨자, 대문자, 자간, 하이퍼링크, 글꼴 이름) | **필드는 평문으로 풀려 나온다**(머리글 쪽 번호가 모든 쪽에 같은 값). 쪽 번호를 올바르게 찍으려면 IR이 필드를 구분해야 한다 — 미해결 |
| 문단 간격(전/후), 줄 간격(auto 240분율/exact), 들여쓰기(왼/오/첫 줄), 정렬, 탭(위치/정렬/리더), 테두리, 배경, keep_with_next/keep_together | 줄 나눔·높이는 없음(우리가 계산) |
| 구역별 용지·여백·방향, 머리글/바닥글(기본/첫쪽/짝수쪽), 다단, 구역 나누기 종류, 강제 쪽/단 나누기 | 조판 결과(쪽 번호, 쪽 수) 없음 |
| 표(열 너비, 행/열 병합, 셀 배경·테두리·여백, 머리글 행 반복), 목록(종류·단계·시작 번호·nested), 그림(표시 크기 EMU, base64 데이터), 글상자(앵커·감싸기), 각주/미주 본문 | 떠 있는 그림의 글 감싸기 위치(일부만) |

## v1 범위 (구현 순서)
1. **문단**: 글자 서식, 정렬(왼/가운데/오른/양쪽), 들여쓰기, 간격, 줄 간격, 탭, 형광펜·밑줄·취소선·첨자.
2. **줄바꿈**: 공백 기준(영문), **한글·한자·가나는 글자 단위**(금칙: 줄 첫머리 닫는 문장부호, 줄 끝 여는 문장부호 방지). 양쪽 정렬은 공백에 여유를 배분(BetterOffice와 같은 방식).
3. **쪽 나눔**: 용지·여백, 강제 쪽 나누기, 구역 나누기, 과부/고아 줄 방지(2줄), keep_with_next/keep_together.
4. **목록**: 번호(decimal, 알파벳, 로마자)·글머리표, 단계별 들여쓰기.
5. **표**: 열 너비·병합·테두리·배경·머리글 행 반복. v1은 **행을 쪽 사이에서 쪼개지 않는다**(쪽보다 높은 행은 잘림 — 한계로 표시).
6. **머리글/바닥글**, 그림(인라인), 각주(v1: 문서 끝에 모아 표시).
v1 비범위: 다단 흐름, 떠 있는 그림·글상자의 글 감싸기, 수식·차트, 변경 내용 추적, 쪽 번호 필드(위 한계), 각주의 쪽 하단 배치, 도형.

## 단위
twips → px: `px = twips / 15` (96dpi). half-point → px: `px = half_pt × 2/3`. EMU → px: `px = emu / 9525`.

## 정확도 기준 (측정으로 검증, PRD 11-1)
- **정답 기준**: BetterOffice(`ae7a003`)의 조판 결과. 하네스(`docs/phase3/spike/`)가 이미 쪽 수와 쪽별 글자를 낸다. 두 엔진이 같은 글꼴을 쓰도록 시험에서는 모든 글꼴을 한 글꼴(Carlito)로 통일한다.
- **지표**: (a) 쪽 수 일치율, (b) 쪽별 첫/끝 글자 일치율, (c) 줄 수 차이. 목표(가설, 측정 후 보정): 샘플에서 쪽 수 일치 ≥ 90%.
- BetterOffice가 "Word와 같다"는 보증은 아니다. 이 비교는 **우리 구현이 정교한 엔진과 얼마나 같은가**를 재는 것이며 Word 일치도는 따로 측정하지 못했다(Word 없음).

## 위험·한계 (기록)
- 글꼴: 기기에 없는 글꼴은 대체되어 줄/쪽 경계가 달라질 수 있다. 맑은 고딕 등 Windows 전용 글꼴은 다른 OS에서 대체된다.
- 필드(쪽 번호) 미해결(위 표). 각주 쪽 하단 배치 미구현. 큰 문서(수백 쪽)의 시간·메모리는 미측정.
- 조판은 신뢰할 수 없는 입력 위에서 돈다: 쪽 수·표 크기·글자 수에 상한을 두어 무한 루프·메모리 폭주를 막는다(M5 변이 시험).
